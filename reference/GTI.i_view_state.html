GTI.i_view_state()

Keep the reader’s view of the table, for when the page is opened again, and let them undo their changes to it.

Usage

Source

GTI.i_view_state(
    url=True,
    storage=False,
    undo=True,
)

The view is the table’s filters, sort, search, page, page size, hidden columns, and the column its rows are grouped by, and the height of a body that scrolls (see i_scroll()) as the reader drags it (not the rows selected, or the columns’ widths). As the reader changes it, it can be kept in the page’s URL (url=), so that reloading the page, or sharing its link, opens the table as it was; and in the browser’s storage (storage=), so that the reader finds it as they left it when they come back to the page. The table’s info panel then has a button that goes back to the view the table is first shown with (see i_view()), which is also what’s kept as no view at all.

In the URL, the view is in the query string, with each part of it named after the table’s ID (e.g., ?towny.filter=population_2021+%3E%3D+10000&towny.sort=-population_2021, the filter written as i_view() takes it as text), so that tables with different IDs keep their own views, and the page’s other parameters are left alone. A link that has the view of a table opens it with that view, rather than the one in the browser’s storage. A part of the view the table can’t have (say, a filter on a column that has none, after the table is changed) is left out, with a warning in the browser’s console, and the rest kept.

With undo= (the default), the control bar has buttons that undo and redo the reader’s changes to the view, as do Ctrl+Z and Ctrl+Y (⌘Z and ⇧⌘Z on a Mac) in the table. Typing a search, or changing one filter, a little at a time is one change; going to another page isn’t one, but is undone with the change after it. Resetting the view is a change too, so it can be undone. The changes are kept while the page is open, not with the view.

The view is kept by the table’s ID, so the table needs one: set it with GTI(id=) (or with_id()). Undo alone (url=False, storage=False) doesn’t need one.

Parameters

url: bool = True

Whether to keep the view in the page’s URL (the default).

storage: bool = False

Whether to keep the view in the browser’s storage (localStorage), for the page.

undo: bool = True
Whether readers can undo and redo their changes to the view (the default).

Returns

GTI
The GTI object is returned.

Examples

Here’s a table of Ontario’s municipalities whose filters, sort, search and page are kept in the page’s URL as they’re changed, so that a link to the page shows what the reader sees; the undo and redo buttons in the control bar step back and forth through those changes.

from great_tables import GTI
from great_tables.data import towny

(
    GTI(towny[["name", "status", "population_2021"]], rowname_col="name", id="towny")
    .fmt_integer(columns="population_2021")
    .i_cols_filter(columns=["status", "population_2021"])
    .i_view_state()
)
